# PicHarbor 移动端共同产品规范

更新：2026-11-18。手机端已整合到 [PicHarbor-Mobile](https://github.com/Cc-Cece/PicHarbor-Mobile/tree/feat/mobile-framework-parity)，页面规范以该仓库的 [specs](https://github.com/Cc-Cece/PicHarbor-Mobile/tree/feat/mobile-framework-parity/specs) 和用户确认预览为准，页面蓝本更新为 iOS `e0c495c`。
本文继续记录通用业务与协议不变量；与新页面规范冲突的导航、仓库边界和入口位置由新规范覆盖。

## 产品边界

- Android 与 iOS 统一在 PicHarbor-Mobile 的各自子目录；gpmc 继续独立，是通用业务与协议的唯一维护源，客户端使用同内容锁定快照。
- Android 包名 `com.cccece.picharbor.mobile`，最初版本为 `2.0.0-alpha.1` / versionCode 1，框架对齐版本为 `2.0.0-alpha.2` / versionCode 2。
  它是可与旧版共存的新应用，不导入旧应用账号、设置、历史或任务。旧签名不得被替换或删除。
- iOS 保持 `com.cccece.picharbor`、原有用户数据与原生界面，兼容引入共享业务核心。
- SwiftUI 与 Compose 分别维护；通用功能、页面归属和业务结果一致，平台交互细节使用原生行为。
- 不包含桌面重构、自动公开发布、卸载旧应用、删除用户媒体。

不得用占位页面、握手门控或模拟结果作为功能完成证据。实验功能仍须有实际实现及单独验收状态。
平台差异必须对应可验证的系统能力限制，缺少实现本身不构成例外。

## 默认行为

原画质模式 `original`（界面“不计配额原画质”，实际配额以服务端为准）；Live Photo 原始资源联合配对；
原始与编辑后资源在平台能提供时均保留；初次自动备份关闭，确认范围后开启；范围为全部已授权内容；
仅 Wi-Fi；单向相簿同步关闭；自动归档开启，14 天（允许 1–90 天）；语言与外观跟随系统。
恢复默认仅重置当前账号业务偏好，关闭自动备份并要求确认范围，保留媒体、账号、记录、语言和外观。

## 业务与接口不变量

- 原生 UI 只负责展示与操作输入，不能从字节发送完或 HTTP 成功推导业务完成。
- 共享入口 `dispatch_json(action,payload)`，协议版本 2。客户端启动时核对必要 action。
  版本不兼容、核心缺失或未知 action 必须明确失败，不扩大范围，不切换本地备用业务规则。
- 核心任务增加 `revision`：创建为 0，实际状态变化递增，同状态重放不递增。
  客户端串行接受决策并核对持久快照修订，拒绝迟到事件；取消任务不能复活。
- `transition(...,to="done")` 必须显式传入 `cloud_confirmed=true` 或已有相同确认证据。
  Live Photo 必须确认两资源指向同一云端项目；同名、近似时间、两个独立文件上传成功均不是配对证明。
- 新增 `select_proxy`：只接受不含秘密的节点名称、可用性、延时和策略，返回 node/direct/waiting。
  明确允许直连时才可直连，正常连接优先保持；失败节点按健康数据切换。
- 新增 `select_versions`：输入 policy（both/original/current）、available（平台明确提供的版本列表）和 has_edits（true/false/null），输出 versions。不能把当前文件冒充编辑前原件；已知有编辑但缺少所选资源时明确失败。未知编辑历史时 both 保留所有可用版本。
- `Api.upload_file(...,raw_response=True)` 可取得未经重构的上传响应，默认仍返回原有解码结果。
  配对提交保留原始响应及提交前持久化标记，未知提交结果先查询，不能盲目重交。
- 核心决策无状态；客户端原生数据库保存权威快照，原生任务表为展示/执行投影。
  iOS 从旧核心文件兼容导入后改写原生数据库；Android 新应用不导入旧数据。
- 网络偏好可改变未完成任务的执行条件，内容策略随任务创建固定。手动暂停不能被自动恢复覆盖。
- 取消移除保留内部记录并阻止同版本自动重入队，用户仍可手动备份。不删除本机或云端媒体。
- 电脑直传使用现有 v1 TLS 固定证书、P-256 设备身份、配对 MAC 与会话签名；接收方确认后才发资源。
  上传清单、偏移、完整哈希与接收完成结果均需核对；离开前台停止传输。

## 诊断与发布

日志默认常开，保留 14 天或 64 MiB，任一达到即滚动；日期范围默认全部现存日志。
导出 ZIP 包含 JSONL 与同源可读文本，披露真实覆盖范围。不得写入账号、凭据、媒体或完整路径；
文件名只允许 basename，平台可以采取更严格的不记录策略。

Android 新应用使用独立固定密钥、仓库外受保护文件与独立 CI secrets，构建前后核对证书。
不得自动为已建立的应用身份重新生成密钥。iOS 保留无签名 IPA 构建方式。

开发交付和实机验收分开记录。没有 Android/iPhone 实机与真实云端证据时，不能宣布最终统一验收通过。
